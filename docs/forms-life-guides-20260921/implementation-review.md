# 생전·사후 자료 가이드 구현

기준 브랜치: `codex/forms-redesign-preview-20260920` (`8014a2986a3cb85c617be40e8024c585cb4854b3`).

작업 중 추가된 자료 건수·모바일 표시 수정 `c11b34ab6769191bf18ff7257d1deac8f1943f42`도 통합했다. 두 작업의 테스트를 함께 유지한다.

## 사용자 흐름

1. 자료실에서 생전 준비 또는 상속 발생 후 가이드로 이동한다.
2. 생전 5개 주제, 사후 6개 주제에서 할 일과 해당 자료의 용도를 확인한다.
3. 원본 자료 상세에서 대상·사용 시점·준비자료·사용 순서·주의사항을 확인한다.
4. 직접 작성하는 준비자료 6종은 작성 목적과 결과물 설명, 비교표 및 관련 서류를 제공한다.
5. 자료 상세와 준비자료에서 해당 가이드의 주제로 돌아갈 수 있다.
6. 생전 가이드의 재산정리 단계에서 조회사이트 9종을 펼쳐 공식 경로·본인인증·확인 항목·기록 예시를 확인하고, 정리 노트의 해당 질문으로 이동한다.
7. 상속 발생 후에는 가족관계 증빙, 재산·채무 조회, 유족연금 확인 단계에 나누어 9종의 안내를 제공한다. 신청 자격·신청인 인증·준비서류·대리 신청·온라인 또는 방문 이용 방법을 확인한 뒤, 결과를 해당 정리 노트 질문에 기록한다.

정리 노트의 질문 옆에서도 생전·상속 후를 구분해 해당 조회사이트와 기록 예시를 볼 수 있다. 공식 사이트는 새 창으로 열리며 인증정보·조회 결과의 자동 수집이나 자동 입력은 추가하지 않는다. 연금은 생활비 점검표의 수입 조건에도 연결하고, 사후 조회는 신청인 본인의 인증·자격 확인 절차로 안내한다. 사망자의 인증수단을 대신 사용하도록 안내하지 않는다. 조회서비스 안내는 기존 원자료 177건과 별도이며, 구체적 출처와 조회 범위는 `lookup-sources.md` 및 `post-death-lookup-sources.md`에 기록한다.

사후 조회는 안심상속 통합신청과 기관별 후속 확인을 구분한다. 조회 접수와 지급·명의이전은 별도이며, 결과 대기·미조회는 재산이나 채무가 없다는 뜻으로 처리하지 않는다. 보험 수익자와 유족연금 수급 자격, 사망일 기준 금액과 현재 금액도 따로 확인하도록 안내한다.

사후 가이드의 재산 조회와 승인·포기 검토는 병행할 수 있도록 안내한다. 단계 번호는 탐색 순서이며 필수 완료 순서나 자동 기한 계산을 뜻하지 않는다. 법원 분할사건용 명세표는 일반 재산정리표와 구별했다.

## 데이터 보존

- 기존 177건의 시점 미분류 124건을 해소했다. 생전 27건, 사후 56건, 조건부 양 시점 94건이다.
- 자료별 사용 설명 177건을 추가했다. 조건부 공용 분류에는 두 시점의 실제 사용 조건을 명시한다.
- 기존 자료 103개 대표카드, 보관 9건, 원본 파일·해시·출처·수집 근거·법적 검증 상태를 유지한다.
- 가이드 64개 연결은 실제 자료 54종을 가리킨다. PLAN-01·02·04·06과 휴면예금·미수령 주식 자료는 양 시점 가이드에서 사용한다.
- manifest의 변경 허용 필드는 `description`, `resource.facets.timing`뿐이다. 과거 기준 파일을 고치지 않고 검증 과정에서 이 두 필드만 현재 작성 데이터와 대조한다.
- 입력 내용은 기존처럼 탭 내 메모리에서만 유지하며 상담 신청으로 자동 전송하지 않는다.

## 검증

- `npm run test:forms`: 54개 테스트 및 177건 스키마·원본 보존 검사 통과.
- `npm run lint`: 통과.
- `npm run build`: 프로덕션 빌드와 TypeScript 검사 통과.
- `npm run test:forms-routes`: 자료실·준비자료 6종·가이드 3페이지·생전 9종과 상속 후 9종의 단계별 앵커·신청 안내·정리 노트 입력칸 연결·잘못된 경로 404·원본 PDF 응답 검사 통과. 정리 노트의 생전·상속 후 도움말과 가이드로 돌아가는 링크도 실제 렌더링된 HTML에서 확인했다.
- 실제 UI 브라우저 검증은 실행환경에서 차단됨: 로컬 agent-browser의 소켓 생성 오류와 클라우드 브라우저의 로컬 URL 접근 차단. 이 기록은 시각 검증 완료를 의미하지 않는다.

## 범위상 남아 있는 점

- 기존 목적·자산 태그는 이번 시점·설명 변경 범위에 포함하지 않았다. 예를 들어 NTS-IG-04의 기존 gift 태그는 보존하되 사용 설명은 태아 상속공제 증명 용도로 한정했다.
- 원본의 최신 법령 적용 여부를 검증 완료로 변경하지 않았다. 구자료의 연도와 기관별 최신 양식 확인 안내를 유지했다.
