# 생전 조회 서비스 연결 검토

확인일: 2026-09-21. 구현: `lib/forms/lookup-services.ts`.

9개 조회 경로는 기존 자료 177건에 추가하는 서식이 아니라, 생전 상담 노트의 입력을 돕는 별도 안내 데이터다. 원본 manifest·서식 수·법정기한·출처 검증 상태는 수정하지 않았다. 이 문서는 공개 페이지와 제공기관 안내의 확인 범위를 기록하며, 로그인 후 개인조회가 정상 작동했다는 확인서는 아니다.

## 기록 원칙

- 기록 대상은 관계·기관·자산 또는 부담 종류·대략 금액·확인일·남은 질문이다. 주식은 확인한 수량과 평가금액을 구분한다. 주민등록번호·계좌번호·증권/주권번호·상세 주소·로그인 정보·인증정보는 예시와 입력 안내에서 제외한다. 공식 제공처가 본인확인을 위해 받는 정보와 이 사이트의 상담 노트 기록은 별개다.
- 생존 가족의 금융정보는 명의자 본인이 직접 인증한다. 직접 이용이 어렵다면 해당 기관이 인정하는 대리 경로를 확인한다. 가족 계정이나 인증수단을 대신 사용하는 우회 안내는 없다.
- 조회 미실행·인증 실패·결과 준비 중·자료 미제공은 `unconfirmed_items`에 남길 내용이며 재산·채무가 없다는 판정이 아니다.
- 은행·증권·보험·연금·휴면 조회의 같은 자산은 한 번만 정리한다. 배당내역에서 이미 수령한 금액은 현재 계좌잔액과 다시 합산하지 않는다. 등기와 공시가격은 같은 부동산을 확인하는 서로 다른 근거다.
- 대출잔액·대출한도·보증금액·근저당 채권최고액은 서로 다르다. 보증과 담보를 확정 채무잔액에 기계적으로 합산하지 않는다.
- 월 연금수입·보험 보장금액·계좌 적립금·공시가격은 의미가 다르다. 예상 연금 월수입을 상속재산총액으로 합산하지 않는다.

## 연결 검증

`LookupTarget.label`은 `planning-content.json`의 실제 질문 문구와 일치시켰다. 연결은 PLAN-01의 `asset_notes`·`debt_notes`·`family_context`·`unconfirmed_items`, PLAN-04의 `income_notes`를 사용한다. 계좌번호 등 개인 조회 원문을 사이트가 가져오거나 저장하는 기능을 추가하지 않았다. 관련 원본 자료 연결은 P0-06·P6-02·P6-05·P9-10으로 한정했다.
