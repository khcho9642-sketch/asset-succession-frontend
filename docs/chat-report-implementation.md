## 사용 흐름

1. 메인의 진단 버튼으로 `/precheck`에 들어간다. 한 문장에 가족·자산·채무·목표를 함께 입력할 수 있다.
2. 입력에서 확인 가능한 내용과 원문 근거를 임시 사실로 정리한다. 빠진 내용만 추가로 확인한다.
3. `입력 내용 확인`에서 항목을 수정한다. 작성 중인 메시지나 저장하지 않은 수정이 있으면 보고서 생성은 대기한다.
4. 선택한 분야의 금액·적용 조건을 확인한다. 기준안과 대안의 추정 세액을 즉시 표시하며, 계산 조건이 부족하면 보고서 생성 버튼은 비활성화된다. 새 대화 진단에서는 세액 비교를 제외할 수 없다.
5. 계산 가능한 조건을 최종 확인한 후 `/report-preview`의 추정 세액 7페이지 보고서로 연결한다. 첫 페이지에 기준안·대안의 세액과 차이가 표시된다. 기존에 저장한 사실 정리 결과는 `입력 요약 · 세액 계산 전`으로 구분하며, 같은 화면에서 계산 조건을 추가해 동일 진단 ID의 세액 보고서로 전환할 수 있다.

기존 단계형 입력은 `/precheck/form`, 가상 사례 이미지 열람은 `/sample-report`다. 네 분야는 하나의 대화 화면을 사용하며 `?purpose=inheritance`, `gift`, `capital_gains`, `business_succession`으로 시작 주제를 전달할 수 있다. 새 가업 진단은 가업상속 계산을 기본으로 시작하고, 명시적인 생전 증여 요청 및 기존 저장된 가업주식 증여 계산은 보존한다.

## 실제 AI와 입력 정리 모드

서버 환경변수 `AI_GATEWAY_API_KEY`와 `AI_DIAGNOSIS_MODEL`이 모두 있으면 AI SDK의 스트리밍 대화를 사용한다. 모델 식별자는 해당 Gateway 계정에서 지원하는 값을 설정한다. API 키는 브라우저로 보내지 않는다.

설정이 없으면 화면에 **AI 연결 전 · 입력 정리 모드**라고 표시한다. 이 모드는 제한된 규칙으로 입력을 정리하며 생성형 AI 상담을 했다고 표시하지 않는다. 입력·수정·확인·보고서 연결은 사용할 수 있다. 실제 연결이 실패하면 오류와 재시도를 제공한다.

모델의 사실 제안은 최신 사용자 메시지의 실제 인용과 일치할 때만 반영한다. 전송 제한, 같은 출처 검사, 시간 제한, 오류 내용 정제와 중복 전송 방지를 포함한다. 모델이 제안한 값도 고객 확인 전에는 확정하지 않는다.

## 보고서의 범위

- 확정된 부동산 25억 + 15억, 금융자산 10억은 기존 보고서에 50억으로 전달한다. 합계와 내역을 이중 합산하지 않는다.
- 일부 자산의 정정이 나머지 자산을 지우지 않도록 충돌을 남기고 확인을 받는다. 범위·대략·불명확한 금액은 임의의 단일 금액으로 바꾸지 않는다.
- 자녀 수에서 성년 여부를 추정하지 않는다. 부친 소유를 작성자 본인 소유로 바꾸지 않는다. 채무를 말하지 않았다는 이유로 0원 처리하지 않는다.
- 확인한 계산 입력이 있으면 별도 계산 모듈에서 공제·과세표준·세율·세액공제를 적용하고 전체 7페이지에 동일한 결과를 표시한다. 과거에 계산 없이 저장한 자료는 입력 요약으로 보존하며, 추정 세액 보고서 완성을 안내한다. 시가를 과세표준으로 간주하거나 세액·차액을 모델이 만들어내지 않는다.
- 산출물은 사전진단이며 전문가 검토 완료를 뜻하지 않는다. 미확인 사항과 추가 확인할 쟁점을 함께 보여준다.

## 저장과 실행

대화 초안은 현재 브라우저 탭의 세션 저장소에 보관한다. 저장소가 차단되면 메모리로 같은 탭 내 이동을 지원하며 새로고침 시 사라질 수 있음을 알린다. 서버 고객 DB, 계정 간 동기화, 가족 공유 링크는 이번 범위에 없다. 보고서 주소의 식별자는 공유 가능한 영구 문서 주소가 아니다.

`npm ci` → `npm run dev`. 운영 빌드는 `npm run build` → `npm start`다. `/api/diagnosis` 때문에 기존 정적 `out/` 내보내기를 정상 Next.js 서버 빌드로 변경했다. 기존 Vercel 프로젝트의 Next.js preset, 실제 package.json 위치, Node.js 22 및 Output Directory override 해제를 확인해야 한다. 새 프로젝트나 유료 서비스를 만들지 않는다.

## 검증

로컬에서 lint, TypeScript, 기존 엔진 28개 및 채팅·서버 단위 테스트 26개가 통과했다. 실제 Next 서버에서 키 없이 API 입력·출처·크기·오류 처리 23개 사례가 통과했다. 설치한 AI SDK로 모의 스트림 형식도 확인했다.

GitHub CI에 모바일 390px·데스크톱 1440px 대화 → 수정 → 확인 → 보고서, 입력 복구, 키 없는 모드, 모의 AI 스트림, 실제 인쇄 PDF의 A4 7페이지 확인을 추가했다. 로컬 브라우저·PDF 검사는 실행 환경 제약으로 실행하지 않았다. 최종 실행 여부와 결과는 해당 커밋의 CI를 기준으로 확인한다.

이번 작업 환경에는 실제 AI 키가 없으므로 실제 모델 응답 품질·속도·비용은 검증하지 않았다. Vercel 관리 API 접근도 거절되어 기존 프로젝트의 배포 설정과 환경변수는 수정하지 않았다. 실제 AI 사용 전 기존 프로젝트에서 환경변수를 설정하고 Preview에서 동일 대화 흐름을 확인한다.
