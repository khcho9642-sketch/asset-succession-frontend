## 내용 검토 결과

- 기관이 발행한 서식과 구별해 모든 자료에 `자체 제작 · 상담 준비자료`를 표시합니다. 109건 수집 작업 또는 177건 기관 자료 집계에 합산하지 않습니다.
- PLAN-03과 PLAN-05는 생전 준비로 태깅했습니다. 나머지는 생전 설계에 우선 활용하면서 상속 발생 후에도 사실·자금·상담 자료를 정리할 수 있어 두 시점에 태깅했습니다.
- 주민등록번호·계좌번호·연락처·전체 주소 입력을 요청하지 않습니다. 사람은 관계명이나 별칭으로 기록합니다. 화면에서 원본 파일을 업로드하도록 요구하지 않습니다.
- 금액 질문은 총 5개입니다. 만원 단위를 명시하고 선택 입력으로 두었습니다. 세액·절세액·자금 부족액을 자동 판정하지 않습니다.
- 증여·대여의 법적 분류, 과거 거래의 합산 범위, 유언의 효력, 신탁·후견 이용 자격, 금융상품 추천을 입력 선택만으로 판정하지 않습니다.
- PLAN-05는 상담 질문 자료입니다. 유언장·신탁계약서·후견계약서의 자동 생성 서식으로 표시하지 않습니다.
- 법정 기간·공제액·세율·제출기한을 수치로 기입하지 않았습니다. `planning_windows`는 준비 전에 확인할 조건만 담고 모두 `pending` / `qualitative_only`로 유지했습니다. 개인별 창의 열림·닫힘이나 D-day를 계산하지 않습니다.

## 화면 구현 계약

1. `sections[].questions[]`를 순서대로 렌더링합니다. 지원 타입은 `text`, `textarea`, `number`, `select`, `multiselect`입니다. `required`는 모두 `false`입니다.
2. `options`는 `{ value, label, exclusive? }`입니다. `exclusive: true`인 ‘없음/확인 필요’ 항목은 같은 질문의 다른 선택과 동시에 선택되지 않도록 합니다. 이러한 항목을 선택하면 기존 선택을 해제하고, 다른 항목을 선택하면 배타 항목을 해제합니다.
3. 입력은 화면 메모리에만 유지합니다. 별도 동의 없는 자동 전송·서버 저장·브라우저 영구 저장을 추가하지 않습니다. 질문은 적더라도 자유 입력에서 민감정보가 들어갈 수 있으므로 관계명 사용 안내를 보입니다.
4. 요약은 `summary_template`의 `{{question_id}}`를 입력값으로 한 번 치환합니다. 선택지는 코드가 아닌 `label`, 복수 선택은 쉼표로 표시합니다. 사용자 입력값에 들어 있는 중괄호를 다시 치환하지 않습니다.
5. 빈 값과 숫자 0을 구분합니다. 빈 값은 `미입력 · 상담 시 확인`, 숫자 0은 `0`으로 표시합니다. 금액 입력의 음수·NaN·Infinity는 유효한 값으로 내보내지 않습니다.
6. 요약은 일반 텍스트로 미리 보여줍니다. 사용자가 눌렀을 때 복사 또는 UTF-8 `.txt` 내려받기를 제공합니다. 복사에 실패하면 실패 메시지를 보이고 다운로드를 대안으로 유지합니다.
7. PLAN-06에서 다른 점검표를 선택해도 내용이 자동 전송되었다고 표시하지 않습니다. 자료 사이의 입력을 이어받으려면 실제로 구현한 동작과 전달 범위를 사용자에게 표시합니다.
8. 상담 전달을 연결할 때에는 사용자가 최종 요약을 확인한 다음 명시적으로 실행하게 합니다. 이번 데이터 자체에는 자동 발송·등록 동작이 없습니다.
9. 추천 영역에는 준비 자료를 우선 표시할 수 있지만, 자료실에 직접 들어온 사용자의 전체 자료 목록을 이 질문으로 가리지 않습니다.

## 검증

`validation-report.json`에 결과를 기록했습니다. 자료 ID 유일성, 각 자료의 6~12개 질문 조건, 전체 선택 입력, 질문 ID와 요약 치환식의 1:1 일치, 선택지 유일성, 금액 단위와 하한, 공용 planning-window 스키마의 필수 필드·열거값을 확인했습니다. 오류는 없습니다.

이 검증은 데이터의 구조·문구 범위를 확인한 것입니다. 전용 JSON Schema 엔진 검증, 브라우저 입력·다운로드 동작과 법령·상품조건 검증은 수행하지 않았습니다. 후자는 수치나 효력 판정을 제공하지 않는 이번 콘텐츠에서 검증 완료로 표시하지 않습니다.
